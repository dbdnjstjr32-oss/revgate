## 제1장. RevGate 개요, 핵심 원칙 및 시스템 한도

### 1.1 RevGate란?

**RevGate**는 제조·가공 발주처와 외주 가공업체 사이에서 도면 리비전 변경 누락으로 인한 오가공 사고를 막기 위해 설계된 **3D STEP B-Rep 변경점 분석 + 제조 사양·2D 도면 통합 리뷰 + 가공 착수 승인 증빙 시스템**입니다.

1. **STEP(ISO 10303-21) 두 리비전(Base vs Target) 비교**: OpenCASCADE B-Rep 엔진이 면·홀·두께·추가/삭감 살을 계산하고 자동 정합(실패 시 3-2-1 수동 정합)을 수행합니다.
2. **제조 사양(`SpecCardV2`) + 2D 도면(PDF/DXF/사양서) 통합 관리**: 공정·재질·열처리·표면처리·공차·나사/인서트·적층 사양의 변경점을 `CRITICAL` / `MAJOR` / `INFO` 등급으로 비교합니다.
3. **불변 승인 스냅샷 & 구버전 자동 무효화(`SUPERSEDED`)**: 가공업체가 OTP 인증 후 검토·승인하면 해당 시점의 형상·사양·체크·3D 핀을 SHA-256으로 봉인한 **가공 착수 승인 증빙 PDF**가 생성되며, 이후 설계나 도면이 수정되면 기존 승인은 자동으로 구버전(`SUPERSEDED`) 처리됩니다.

### 1.2 현장에서 반드시 지켜야 할 3대 원칙

1. **3D 치수는 공칭 참고치이며 2D 도면과 제조 사양이 최우선입니다.**  
   승인 PDF 법적 고지에 명시되어 있듯, 3D STEP에서 측정되는 치수와 ISO 탭 추정 힌트는 **공칭 형상 기준의 참고치**입니다. 실제 가공 공차, 끼워맞춤, 나사 규격, 표면처리는 반드시 첨부된 **2D 도면(PDF/DXF)**과 **제조 사양 카드**를 기준으로 가공해야 합니다.
2. **승인은 시점 스냅샷이며 변경 발생 시 즉시 구버전(`SUPERSEDED`)이 됩니다.**  
   이미 `APPROVED` 된 링크라도 Target 리비전 이후 **새 리비전이 등록(`NEW_REVISION`)**, **제조 사양이 수정(`SPEC_UPDATED`)**, **2D 첨부 도면이 추가/삭제(`DRAWING_UPDATED`)**되면 기존 승인은 즉시 `SUPERSEDED` 상태가 됩니다.
3. **`SUPERSEDED` 적색 경고 배너가 뜨면 즉시 가공을 멈춥니다.**  
   `SUPERSEDED` 상태에서는 과거 승인 링크의 원본 STEP 다운로드가 시스템 차원에서 즉시 차단되며, 현장 작업자는 발주처에 최신 리뷰 링크를 요청해야 합니다.

## 제2장. 발주처 기구설계자 가이드

**동선:** `/login` → `/workspace` → `/parts/[partId]/diffs/[diffId]`

### 2.1 로그인 (`/login`)

1. `/login` 페이지(**발주처 로그인 (Magic Link)**)로 이동합니다.
2. **업무용 이메일** 입력란에 본인의 워크스페이스 계정 이메일(로컬 테스트 기본 계정 예시: `designer@revgate.local`)을 입력한 뒤 **로그인 링크 받기** 버튼을 누릅니다.
3. **링크 열기**:
   - **운영 환경**: 수신된 업무 이메일에서 매직 링크를 클릭합니다(유효시간 **15분**, 1회용).
   - **로컬 개발 환경 (`rg:dev:outbox`)**: 화면 하단에 노란색 **`DEV · rg:dev:outbox`** 박스가 나타나며, 발급된 **로그인 링크 열기** 버튼을 바로 눌러 로그인할 수 있습니다.
4. 인증이 완료되면 7일간 유효한 세션 쿠키(`rg_sid`)가 발급되고 `/workspace`로 이동합니다.

### 2.2 부품 등록 및 STEP 리비전 업로드 (`/workspace`)

#### 1) 새 부품 등록
좌측 상단 부품 등록 영역에서 아래 정보를 입력하고 **부품 등록** 버튼을 클릭합니다.
- **품번** (Part Number, 워크스페이스 내 중복 불가 — 중복 시 `PART_EXISTS`)
- **품명** (Part Name)
- **소재** (기본 재질, 선택 — 이후 리비전 제조 사양 카드에 기본 상속됨)
- **후처리** (기본 표면처리, 선택)

#### 2) STEP 파일 업로드 및 자동 페어 Diff 실행
부품을 선택한 뒤 중앙의 **STEP** 드롭존(`.step` / `.stp`, 파일당 최대 50 MiB)에 파일을 끌어다 놓거나 선택합니다.
- **단일 업로드**: 1개의 STEP 파일을 올리면 새 리비전이 생성되어 `q-ingest` CAD 파싱(`QUEUED → PARSING → READY`)이 진행됩니다. 동일 SHA-256 파일이 이미 해당 부품에 있으면 중복 등록을 막습니다(`REVISION_EXISTS`).
- **2개 파일 동시 드롭 (페어 자동 Diff)**: Base(수정 전)와 Target(수정 후)에 해당하는 STEP 파일 **2개를 한꺼번에 드롭**하면, RevGate가 두 리비전을 동시에 인제스트한 뒤 완료 즉시 **변경점 분석 (B-Rep Diff)**을 자동으로 시작합니다.

#### 3) 진행 상태 모니터링
- 화면은 **1,500ms 간격 폴링**과 **SSE(`DiffProgress`)**를 병행하여 분석 진행 상태(`QUEUED` → `COMPUTING` → `READY` / `NEEDS_ALIGN` / `FAILED`)를 실시간으로 표시합니다.
- 분석이 끝나면 상태에 따라 다음 버튼이 활성화됩니다.
  - 정상 정합 완료(`READY`): **`PR 스타일 리뷰 열기 →`**
  - 좌표계 불일치로 자동 정합 신뢰도 미달(`NEEDS_ALIGN`): **`3-2-1 수동 정합 열기 →`**

### 2.3 3D/2D 리뷰 워크벤치 & B-Rep 변경점 검토 (`/parts/[partId]/diffs/[diffId]`)

#### 1) 화면 레이아웃 (`ReviewWorkbench`)
- **PC 데스크톱 (`1024px` 이상)**: 좌·중·우 3컬럼 구조로 표시되며 상단 바에서 **`[3D 단독 | 3D+2D 분할 | 2D 단독]`** 모드를 즉시 전환할 수 있습니다.
- **태블릿·모바일 (`1024px` 미만)**: **`[3D 뷰 | 2D 도면 (N)]`** 탭과 하단 서랍(`BottomSheet`)으로 동작하며, 모바일 부하를 줄이기 위해 기본 저화질 모델에서 **`고화질` / `고화질 전환`** 토글로 고해상도 메시(`lod0.glb`) 전환이 가능합니다.
- 뷰어 접속 중 **Signed URL은 12분마다 자동 갱신**(`useSignedUrlRefresh`)되므로 장시간 리뷰 중 URL 만료로 화면이 끊기지 않습니다.

#### 2) 3D 비교 뷰 모드
상단 컨트롤에서 아래 6가지 시각화 모드를 전환해 형상 차이를 다각도로 검증할 수 있습니다.
- **`Before (Base)`**: 기준(수정 전) 형상 단독 표시
- **`After (Target)`**: 변경 후(수정 후) 형상 단독 표시
- **`Overlay`**: 두 형상을 겹쳐서 비교
- **`고스트`**: 기준 형상을 반투명 고스트로 두고 Target을 강조
- **`+ 추가 살`**: Target에서 새로 추가된 살(부피 증가 영역) 하이라이트
- **`− 깎인 살`**: Target에서 절삭·제거된 살(부피 감소 영역) 하이라이트

#### 3) 마우스/터치 상호작용 (`회전` · `측정` · `핀 추가`)
- **`회전`**: 모델 궤도 회전 및 확대/축소
- **`측정`**: 두 지점 또는 면/엣지 간 공칭 거리 측정 (짧은 탭 판정 기준: `< 200 ms`, 이동 `< 8 px`)
- **`핀 추가`**: 특정 3D 면 위를 탭하여 좌표(`pin_xyz`)와 면 ID(`face_id`)에 코멘트 핀을 고정하고, 해결 여부를 토글(`resolved`)할 수 있습니다.

#### 4) 자동 정합 실패 시 3-2-1 수동 정합 (`DatumAlignPanel`)
원점이 다르거나 CAD 어셈블리 좌표계가 크게 회전된 경우 Stage 0~2 자동 정합 신뢰도가 `0.50` 미만이 되어 **`NEEDS_ALIGN`** 상태가 됩니다.
1. 우측 또는 전용 패널의 **`DatumAlignPanel`**을 엽니다.
2. **`1차 기준 (평면)`**, **`2차 기준 (평면/홀)`**, **`3차 기준 (평면/홀)`** 순서로 Base와 Target에서 대응하는 평면 또는 원통 홀을 각각 클릭해 지정합니다. (필요 시 캔버스 타겟 `🎯` 스냅 활용)
3. 패널에 **실시간 4×4 강체 변환 행렬 미리보기**가 계산되어 표시됩니다.
4. **`3-2-1 정합 적용 (q-diff-interactive)`** 버튼을 클릭하면 대화형 큐(`q-diff-interactive`)로 즉시 B-Rep Diff를 재계산합니다.
> 참고: 이미 승인 완료된 스냅샷이 존재하는 Diff Run은 `DIFF_LOCKED` 정책으로 재정합이 차단됩니다.

### 2.4 제조 사양(`SpecCardV2`)·2D 도면 관리 & 경고 확인

#### 1) 제조 사양 편집 (`SpecEditor`) & 사양 변경 비교 (`SpecDiffCard`)
리뷰 페이지에서 Target 리비전의 제조 사양을 구조화된 `SpecCardV2` 포맷으로 편집할 수 있습니다.
- **공정(`process`)**: `CNC 밀링(CNC_MILLING)`, `CNC 선반(CNC_TURNING)`, `3D 프린팅 (FDM)(PRINT_FDM)`, `3D 프린팅 (SLA/SLS/MJF)(PRINT_SLA_SLS_MJF)`, `판금(SHEET_METAL)`, `기타/미지정(OTHER)`
- **재질(`material`)** · **열처리(`heat_treatment`)** · **표면처리(`surface_finish`)**(아노다이징 두께 `µm`, 색상, 표면 거칠기 `Ra µm`, 마스킹 노트)
- **일반 공차(`general_tolerance`)**: `ISO 2768-fH`, `ISO 2768-mK`, `ISO 2768-cL`, `사용자 정의(CUSTOM)`, `미지정(UNSPECIFIED)`
- **중요 공차(`critical_tolerances`)**: 위치·공차 사양·데이텀 참조 추가
- **나사·인서트(`threads_and_inserts`)**: 규격, 수량, 깊이, 체결 방식(`직접 탭(TAPPED_DIRECT)`, `헬리코일(HELICOIL)`, `열압입 황동 인서트(HEAT_SET_BRASS)`, `PEM 인서트(PEM)`)
- **적층 사양(`additive_spec`, 3D 프린팅 선택 시)**: 적층 방향(`build_orientation`), 층 높이(`mm`), 충전율(`%`), 벽 수(`wall_loops`), 서포트 노트
- **주문·검사(`order`)**: 수량, 납기, 검사 수준(`검사 없음(NONE)`, `치수 성적서(DIMENSIONAL_SHEET)`, `CMM 리포트(CMM_REPORT)`)

저장하면 Target의 `spec_version`이 1 증가하고 **`SpecDiffCard`**가 Base ↔ Target 사양 차이를 `CRITICAL` / `MAJOR` / `INFO` 등급으로 즉시 재계산합니다.

#### 2) 2D 도면 및 사양서 첨부 (`AttachmentManager`)
- 지원 종류 및 확장자 (각 최대 **25 MiB**):
  - **`2D_PDF`**: `.pdf`
  - **`2D_DXF`**: `.dxf`
  - **`SPEC_SHEET`**: `.pdf`, `.xlsx`, `.xls`, `.csv`, `.txt`, `.docx`, `.doc`
- 업로드는 브라우저에서 SHA-256 해시 검증을 거쳐 저장되며, 업로드된 2D PDF/DXF는 `ReviewWorkbench`의 2D 도면 뷰어에서 3D와 나란히 조회할 수 있습니다.

#### 3) 4대 사양 경고 (`apps/api/app/spec.py`)
| 경고 코드 | 유형 | 발생 조건 및 표시 메시지 |
| :--- | :--- | :--- |
| **`MISSING_MATERIAL`** | **필수 인지 확인 필요** | `"재질(material.grade)이 지정되지 않았습니다."` |
| **`MISSING_TOLERANCE`** | **필수 인지 확인 필요** | `"일반 공차·중요 공차가 지정되지 않았고 Target 리비전에 2D PDF 도면도 없습니다."` |
| **`UNDECLARED_THREAD`** | 참고 주의 경고 | `"3D Diff에 ISO 탭 추정 힌트가 있지만 나사·인서트 사양이 비어 있습니다."` |
| **`MISSING_BUILD_ORIENTATION`** | 참고 주의 경고 | `"3D 프린팅 공정인데 적층 방향(build orientation)이 지정되지 않았습니다."` |

> ⚠️ **주의:** 이미 `APPROVED` 된 외부 리뷰 링크가 있는 Target 리비전에서 **제조 사양을 수정하거나 2D 도면을 추가·삭제하면**, 그 즉시 기존 승인 링크는 **`SUPERSEDED`** 처리됩니다.

### 2.5 외부 리뷰 링크 발급 & 승인 PDF (`ShareLinkPanel`)

1. **`ShareLinkPanel`**에서 가공업체 담당자의 **이름**, **연락처(이메일/전화 식별자)**, **만료 기간(1~90일, 기본 7일)**, **원본 STEP 다운로드 허용 여부(`allow_raw_download`)**를 지정해 리뷰 링크(`/r/{token}`)를 생성합니다.
2. 발주처 설계자는 생성된 링크 URL을 가공업체에 전달하며, 언제든지 링크를 폐기(`REVOKED`)할 수 있습니다.
3. 가공업체가 승인을 완료하면 링크 목록 상태가 **`APPROVED`**로 바뀌고 **승인 증빙 PDF** 다운로드가 가능해집니다.
   - PDF에는 **승인 시각(KST/UTC)**, **Snapshot SHA-256**, **승인자 정보 및 IP 해시**, **Base/Target STEP 및 2D 첨부파일 SHA-256 지문**, **제조 사양 요약 및 변경점**, **3D 형상 변경 체크리스트**, **DFM 확인 목록 및 누락 사양 인지 내역**, **법적 고지**가 영구 박제됩니다.

### 2.6 `ZERO_RETENTION` 환경에서 원본 재드롭 (`RedropPanel`)

워크스페이스가 **`ZERO_RETENTION`** 모드인 경우 인제스트 및 진행 중인 Diff가 완료되는 즉시 서버(MinIO/S3)의 원본 STEP 파일이 파기됩니다(`raw_r2_key` 제거).
- 파기 이후 기존 리비전으로 **새 Diff를 걸거나 3-2-1 수동 정합을 다시 돌리려면** `RAW_PURGED_REDROP_REQUIRED` 안내와 함께 **`RedropPanel`**이 나타납니다.
- 사용자가 로컬 PC에서 동일한 원본 STEP 파일을 다시 드롭하면, 브라우저가 업로드 전에 **SHA-256 해시를 검증**하여 일치하는 경우에만 서버에 원본을 복원하며, 이미 완료된 파싱(`ingest`)은 반복하지 않고 바로 Diff/정합 작업을 이어갑니다.

## 제3장. 가공업체 사장님·현장 작업자 가이드

**경로:** 발주처로부터 전달받은 `/r/[token]` (외부 계정 로그인 불필요)

### 3.1 링크 접속 및 6자리 OTP 인증 (`OtpGate`)

1. 전달받은 `/r/[token]` 링크를 PC 또는 현장 태블릿 브라우저로 엽니다.
2. **`OtpGate`** 화면에서 6자리 OTP 코드 발송을 요청합니다.
   - **실운영 환경**: 링크에 등록된 수신자 연락처로 6자리 OTP가 발송됩니다.
   - **로컬 개발 환경**: 화면 내 노란색 `DEV · rg:dev:outbox`(`dev-otp`) 영역에 표시된 6자리 숫자를 바로 확인할 수 있습니다.
3. 6자리 숫자를 입력해 인증을 완료합니다.
   - OTP 유효시간: **5분** (`300초`)
   - 오입력 허용 횟수: **최대 5회** (5회 실패 시 `OTP_LOCKED` 상태로 잠기며 새 코드를 발급받아야 함)
   - 코드 재요청 제한: **10분당 최대 3회** (`OTP_RATE_LIMITED`)
4. 인증이 통과되면 **24시간** 동안 유효한 외부 세션(`rg_ext_sid`)으로 리뷰 화면이 열립니다.

### 3.2 뷰어 보안 동작 및 현장 태블릿 사용 팁

- **워터마크 & 화면 이탈 보호 블러**: 리뷰 화면 전체에 수신자 정보가 포함된 **`Watermark`**가 표시되며, 창 포커스 이탈이나 캡처 의심 이벤트 시 보안 블러가 작동할 수 있습니다.
- **태블릿/모바일(`<1024px`) 최적화**:
  - 상단의 **`[3D 뷰 | 2D 도면 (N)]`** 탭으로 3D 형상과 첨부된 2D PDF/DXF 도면을 오가며 확인하고, 변경점 목록·승인 카드는 하단 **`BottomSheet`**에서 조작할 수 있습니다.
  - 모바일 기기에서는 기본적으로 경량 메시로 열리며, 상세 육안 확인이 필요할 때 **`고화질` / `고화질 전환`** 토글을 눌러 고해상도로 전환할 수 있습니다.
- **Signed URL 자동 갱신 & 오프라인 큐(`OfflineQueue`)**:
  - 3D/2D 파일 Signed URL은 **12분마다 자동 갱신**됩니다.
  - 공장 내 Wi-Fi 음영 구역에서 체크리스트 체크를 누르더라도 **`sessionStorage` 기반 오프라인 대기 큐(`OfflineQueue`)**에 임시 보관되었다가 네트워크 복구 시 서버와 자동 동기화됩니다.

### 3.3 변경점·2D 도면 검토 & 가공 착수 승인 (`ApproveCard`)

1. **`+ 추가 살` / `− 깎인 살` / `Overlay`** 뷰를 활용해 수정된 부위를 확인하고, 우측 또는 하단 시트의 **3D 형상 변경 체크리스트** 항목을 하나씩 확인 후 체크합니다.
2. 상단 탭/분할 뷰에서 **2D 도면(PDF/DXF)**과 **제조 사양(재질·공차·표면처리·나사/인서트)** 및 Base 대비 **사양 변경점(`SpecDiffCard`)**을 꼼꼼히 대조합니다.
3. **공정별 DFM · 중요부위 확인 (`DfmChecklist`)**:
   - **CNC 공정**: 내측 코너 R (공구 반경) / 박육부 변형·채터링 / 정밀 끼워맞춤 공차 / 코팅·아노다이징 두께 치수 변화 / 데이텀·치구 세팅
   - **3D 프린팅 공정**: 적층 방향 / 오버행·서포트 / 열압입 인서트 홀 / 수축·휨
   - *(체크한 항목은 `dfm_ack`에 저장되어 승인 스냅샷 및 PDF 증빙 `DFM · 중요부위 확인` 표에 공식 기록됩니다.)*
4. **가공 착수 승인 버튼 활성화 4가지 필수 조건** (`r/[token]/page.tsx` 실제 검증 기준):
   - ✅ **모든 3D 형상 변경점 체크 완료** (미완료 시: `"모든 변경점을 체크해야 승인할 수 있습니다."`)
   - ✅ **필수 누락 사양(`MISSING_MATERIAL`, `MISSING_TOLERANCE`) 확인 체크** — 해당 경고가 존재하는 경우에만 표시 (미완료 시: `"누락된 사양 확인란을 체크해야 승인할 수 있습니다."`)
   - ✅ **오프라인 동기화 대기 0건** (미완료 시 예: `"오프라인 대기 2건이 동기화된 뒤 승인할 수 있습니다."`)
   - ✅ **최종 승인 문구 동의 체크**:  
     `"표시된 변경점·제조 사양·2D 도면을 확인했으며, 이 스냅샷(형상·사양·체크·핀) 기준으로 가공 착수를 승인합니다."`
5. 승인 완료 후:
   - **`approved-card`** 상태로 고정되며 스냅샷은 불변(Immutable) 처리됩니다.
   - 발주처가 `allow_raw_download`를 허용해 둔 링크라면 승인 완료 상태에서 원본 STEP 파일 및 2D 첨부 도면을 다운로드할 수 있습니다.

### 3.4 🔴 `SUPERSEDED` 적색 경고 배너 발생 시 현장 행동 수칙

화면 최상단에 빨간색 **`SUPERSEDED`** 배너가 고정 표시되면 **단 한 가지 원칙만 따르십시오.**

> **"해당 링크 기준 가공 착수 및 추가 가공을 즉시 중단하고, 발주처에 최신 리뷰 링크를 요청하십시오."**

- 배너와 승인 카드에는 구버전이 된 원인(`NEW_REVISION` 새 리비전 등록 / `SPEC_UPDATED` 제조 사양 변경 / `DRAWING_UPDATED` 2D 도면 추가·삭제)이 함께 표시됩니다.
- 안전사고 예방을 위해 **`SUPERSEDED` 상태가 된 링크에서는 발주처가 다운로드를 허용했더라도 원본 STEP 및 2D 도면 다운로드가 서버에서 자동 차단(`raw-blocked`)**됩니다.

## 제4장. 공장 전용 무료 도면 접수함 (`/shop/[slug]`)

가공업체가 로그인 없는 고객·외부 거래처로부터 견적 및 리비전 비교 요청을 받을 수 있는 전용 접수 창구입니다.

### 4.1 접수함 개설 (워크스페이스 내부 사용자)

`/workspace`의 **공장 전용 무료 도면 접수함** 패널에서 아래 값을 입력해 개설합니다.
- **슬러그(`slug`)**: 영문 소문자·숫자·하이픈(`-`) 조합 3~40자 (`^[a-z0-9](?:[a-z0-9-]{1,38}[a-z0-9])$`, 중복 시 `SLUG_TAKEN`) → URL `/shop/{slug}` 생성
- **공장명(`shop_name`)** 및 **담당자 연락처(`owner_contact`)**

### 4.2 외부 의뢰인 접수 절차 (`/shop/[slug]`)

접수 링크(`/shop/{slug}`)로 접속한 고객은 로그인 없이 아래 항목만 입력해 제출합니다.
1. **`보내는 분`** (이름/업체명)
2. **`연락처`** (이메일 또는 전화번호)
3. **`품번`** (Part Number)
4. **`수정 전 (v1) STEP`** 및 **`수정 후 (v2) STEP`** 파일 첨부 (`.step`/`.stp`, 각 최대 50 MiB, 두 파일의 SHA-256이 동일할 수 없음 — 동일 시 `IDENTICAL_FILES`)
5. **`변경점 자동 분석 요청`** 클릭 → 브라우저가 두 파일을 직접 업로드·해시 검증한 뒤 **`접수 완료`** 영수증을 발급합니다.
6. 접수된 파일은 해당 워크스페이스 `/workspace` 부품 목록으로 자동 등록되어 곧바로 인제스트(`v1`, `v2`) 및 3D B-Rep Diff 분석이 실행되며, 개설 시 등록한 담당자 연락처(`owner_contact`)로 새 도면 접수 알림이 발송됩니다.

## 제5장. 워크스페이스 관리자(`OWNER`) 및 시스템 운영 가이드

### 5.1 보안 모드 정책 (`TTL_VAULT` vs `ZERO_RETENTION`)

`/workspace` 내 **보안 설정 (Security Mode)** 변경은 **`OWNER` 권한 사용자만** 수행할 수 있습니다(일반 멤버 시도 시 `403 OWNER_ONLY`).

| 정책 모드 | 동작 방식 | 원본 STEP 보관 | 재Diff / 수동 정합 시 |
| :--- | :--- | :--- | :--- |
| **`TTL_VAULT`** (기본값) | 업로드된 원본 STEP을 지정 기간 동안 보관 후 만료 시 자동 파기(`TTL_EXPIRED`) | **30일 ~ 90일** 선택 | 보관 기간 내 별도 파일 없이 즉시 가능 |
| **`ZERO_RETENTION`** | 리비전 인제스트 및 대기 중인 Diff가 끝나는 즉시 `q-purge`가 원본 STEP 파기 | **즉시 파기** (안전 상한: 최대 **24시간** 하드 캡) | **`RedropPanel`**로 원본 재드롭(SHA-256 검증) 필요 |

- **`TTL_VAULT` → `ZERO_RETENTION` 전환 시**: 기존에 이미 `READY` 또는 `FAILED` 상태로 남아 있던 모든 리비전의 원본 STEP에 대해서도 즉시 `q-purge` 파기 작업이 큐에 등록됩니다(모든 변경은 감사 로그 `WORKSPACE_SETTINGS_CHANGED`에 기록).
- **승인 증빙 PDF 보관**: 감사 버킷(`s3_bucket_audit`)은 Object Lock(`GOVERNANCE` 또는 `COMPLIANCE`) 설정 하에 기본 **1,825일(5년)** 동안 WORM 보존되도록 설계되어 있습니다.

### 5.2 로컬·셀프호스팅 실행 및 검증 명령어

`infra/docker-compose.yml`, `Makefile`, `apps/web/package.json` 기준 개발·검증 환경 구성입니다.

- **로컬 인프라 및 서비스 구성**:
  - Postgres (`5432`), Redis (`6379`), MinIO S3 호환 스토리지 (`9000` — 버킷 `revgate-raw-cad`, `revgate-viewer-derived`, `revgate-audit-proofs`), FastAPI 백엔드 (`http://localhost:8000`), OpenCASCADE CAD 워커 (`cad-worker`), Next.js 웹 프론트엔드 (`http://localhost:3000`).
- **주요 검증 명령어 (이 프로젝트에서 확인된 명령어)**:
  - 계약(Contracts) 검증: `corepack pnpm --filter @revgate/contracts run check`
  - 웹 타입·린트·단위 테스트·빌드·E2E: `apps/web`에서 `typecheck`, `eslint . --max-warnings=0`, `vitest run`, `next build`, `corepack pnpm e2e`
  - CAD 워커 단위/골든 테스트: `docker compose -f infra/docker-compose.yml --profile cad run --rm --no-deps cad-worker pytest -q`
  - API 통합 테스트: `docker compose -f infra/docker-compose.yml --profile test run --rm api-tests pytest -q`

### 5.3 로컬 개발 환경과 실운영 환경의 차이 & 참고 사항

1. **이메일·OTP 발송 (`DEV · rg:dev:outbox`)**: 로컬(`dev_outbox=True`)에서는 외부 메일·SMS 게이트웨이 대신 Redis 리스트 `rg:dev:outbox`(`GET /v1/dev/outbox`)에 매직 링크와 6자리 OTP가 기록되어 화면 내 노란 개발 박스로 표시됩니다. 실운영(`REVGATE_ENV=prod` 또는 `DEV_OUTBOX=false`)에서는 비활성화되므로 별도 메일·SMS 전송 연동이 필요합니다.
2. **스토리지 엔드포인트**: 로컬은 `http://localhost:9000` MinIO를 사용하며, 운영 환경에서는 S3/R2 엔드포인트 및 HTTPS 기반 `COOKIE_SECURE=true` 설정을 사용합니다.
3. **협폭 모바일 화면 참고**: 브라우저 실측 검증 기준 약 `357px` 이하의 극소형 화면에서는 상단 헤더가 가로로 미세하게 넘칠 수 있으므로, 실무 도면 검토에는 **태블릿 또는 데스크톱 환경** 사용을 권장합니다.

## 제6장. 현장 트러블슈팅 FAQ 8선 & 전체 에러·경고 코드 사전

### 6.1 현장 트러블슈팅 FAQ 8선

#### Q1. Diff 상태가 `NEEDS_ALIGN`으로 멈췄습니다. 왜 실패했나요?
- CAD 파일 내 Base와 Target의 원점이나 회전 방향이 달라 자동 정합(Stage 0~2) 신뢰도가 기준(`0.50`, `ALIGN_CONFIDENCE_MIN`) 미만으로 판정된 정상 안전장치입니다. (참고로 자동 정합 후 정밀 스냅의 허용 RMS 오차 상한은 `0.020 mm`입니다.)
- **조치**: **`3-2-1 수동 정합 열기 →`**로 들어가 `DatumAlignPanel`에서 두 모델의 동일한 기준 **`1차 기준 (평면)` → `2차 기준 (평면/홀)` → `3차 기준 (평면/홀)`**을 순서대로 지정하고 **`3-2-1 정합 적용 (q-diff-interactive)`**을 누르세요.

#### Q2. `RAW_PURGED_REDROP_REQUIRED` 오류가 뜨며 재Diff나 수동 정합이 안 됩니다.
- 워크스페이스가 `ZERO_RETENTION`(또는 `TTL_VAULT` 기간 만료) 상태여서 서버의 원본 STEP 파일이 파기되었기 때문입니다. 보안을 위해 서버에 원본을 남기지 않은 결과입니다.
- **조치**: 화면의 **`RedropPanel`**에 PC에 보관 중인 동일한 원본 STEP 파일을 다시 끌어다 놓으세요. 브라우저가 SHA-256 해시를 대조해 일치하면 재파싱 없이 원본만 복원하여 Diff/정합을 진행합니다.

#### Q3. 가공업체 화면 상단에 빨간색 `SUPERSEDED` 배너가 떴습니다. 어제 승인했는데 가공을 계속해도 되나요?
- **절대 안 됩니다.** 기존 승인 이후 발주처가 **새 리비전을 올렸거나(`NEW_REVISION`)**, **제조 사양을 바꿨거나(`SPEC_UPDATED`)**, **2D 도면을 수정·삭제(`DRAWING_UPDATED`)**했다는 뜻입니다.
- **조치**: 즉시 해당 공정 착수를 멈추고, 발주처 담당자에게 **최신 리비전이 반영된 새 리뷰 링크**를 요청하세요. (`SUPERSEDED` 링크에서는 원본 STEP 다운로드도 차단됩니다.)

#### Q4. 3D 뷰어 측정값이 2D PDF 도면의 공차/탭 규격과 미묘하게 다릅니다. 어느 쪽으로 가공해야 하나요?
- 무조건 **첨부된 2D 도면(PDF/DXF) 및 제조 사양(`SpecCardV2`)을 우선**으로 가공하십시오.
- 3D 뷰어의 측정과 탭 추정(`ISO M...`)은 STEP 공칭 모델 기준 참고치이며, 승인 PDF 하단 법적 고지에도 2D 도면·제조 사양 우선 원칙이 명시되어 있습니다. 3D와 2D 간 실제 설계 불일치가 의심되면 3D 면에 **`핀 추가`**로 질문 핀을 남기고 발주처 답변을 받으세요.

#### Q5. 3D 형상 변경이 `0건`인데, 왜 승인 요청이 새로 왔나요?
- 치수 형상(STEP)은 동일해도 **재질(예: AL6061 → SUS304), 아노다이징 두께, 일반 공차, 열처리, 나사 방식(헬리코일 추가 등) 같은 제조 사양(`SpecCardV2`)이나 2D 도면**만 변경되었을 가능성이 큽니다.
- **조치**: 리뷰 화면의 **`SpecDiffCard`**와 **2D 도면 탭**에서 변경된 사양 항목(`CRITICAL`/`MAJOR`/`INFO`)을 확인한 뒤 승인하세요.

#### Q6. 체크할 항목은 다 본 것 같은데 `가공 착수 승인` 버튼이 비활성화되어 있습니다.
아래 **4가지 필수 조건** 중 누락된 항목이 없는지 확인하세요 (`r/[token]/page.tsx` 기준).
1. **모든 3D 형상 변경점 체크**: 미체크 시 `"모든 변경점을 체크해야 승인할 수 있습니다."` 안내 표시
2. **필수 누락 사양(`MISSING_MATERIAL` / `MISSING_TOLERANCE`) 인지 확인 체크**: 미체크 시 `"누락된 사양 확인란을 체크해야 승인할 수 있습니다."` 안내 표시
3. **오프라인 대기 건수 0건**: 와이파이 끊김 등으로 대기 건이 남아 있으면 예: `"오프라인 대기 2건이 동기화된 뒤 승인할 수 있습니다."` 안내 표시
4. **최종 승인 동의 체크박스** 선택 여부  
*(추가로 이미 승인이 완료된 상태에서 수동 정합을 다시 시도하면 `DIFF_LOCKED`로 차단됩니다.)*

#### Q7. 현장 태블릿(`1024px` 미만)에서 3D 화면이 흐릿하거나 와이파이가 자주 끊깁니다.
- 화면 이탈/보안 이벤트 시 **`Watermark` 보호 블러**가 일시 적용될 수 있으니 화면 중앙을 다시 탭해 포커스를 복구하세요.
- 모바일·태블릿 환경에서는 메모리 보호를 위해 저해상도 모델로 먼저 열리므로, 상세 확인이 필요할 때 상단의 **`고화질` / `고화질 전환`** 버튼을 사용하세요.
- 현장 와이파이가 잠시 끊겨도 체크리스트 변경은 **`OfflineQueue`(`sessionStorage`)**에 자동 저장되므로, 새로고침/탭 닫기 없이 네트워크가 복구될 때까지 기다린 뒤 동기화 완료 후 승인하세요.

#### Q8. OTP 코드가 안 오거나 `OTP_LOCKED` / `OTP_RATE_LIMITED` 오류가 납니다.
- **5회 연속 오입력 시(`OTP_LOCKED`)**: 보안상 해당 코드는 즉시 잠깁니다. OTP 코드를 새로 요청하여 새 6자리 숫자를 발급받으세요.
- **10분 내 3회 초과 요청 시(`OTP_RATE_LIMITED`)**: 10분 윈도우 내 최대 3회 발급 제한에 걸린 상태이므로 잠시 기다린 뒤 재요청하세요.
- **로컬 테스트 환경**: 실제 문자/메일이 아니라 화면 내 **`DEV · rg:dev:outbox`** 노란 박스에 OTP(`dev-otp`)와 매직 링크가 표시됩니다.

| HTTP | 에러 코드 | 발생 상황 및 해결 |
| :--- | :--- | :--- |
| `400` | **`OTP_NOT_REQUESTED`** | OTP 요청 없이 검증 시도 → 먼저 OTP 코드를 요청한 뒤 검증 |

| `401` | **`OTP_INVALID`** | 6자리 OTP 번호 오입력 (`remaining_attempts` 확인 후 재입력) |
| `401` | **`OTP_REQUIRED`** | OTP 인증을 마치지 않고 외부 리뷰 API 호출 |
| `403` | **`OWNER_ONLY`** | 워크스페이스 보안 설정(`TTL_VAULT`/`ZERO_RETENTION`)을 일반 멤버가 변경 시도 |

| `404` | **`NOT_FOUND` / `NO_APPROVAL`** | 존재하지 않는 리소스이거나, 아직 승인되지 않은 링크의 PDF 다운로드 요청 |
| `409` | **`RAW_PURGED_REDROP_REQUIRED`** | 원본 STEP 파기됨 → `RedropPanel`로 동일 SHA-256 STEP 재드롭 필요 |
| `409` | **`DIFF_LOCKED` / `LINK_LOCKED` / `ALREADY_APPROVED` / `LINK_TERMINAL`** | 이미 승인되어 스냅샷이 잠겼거나 종료된 링크(재정합·재승인·상태 변경 불가) |
| `409` | **`REVISION_NOT_READY` / `DIFF_NOT_READY` / `INVALID_STATE`** | 파싱/Diff 진행 중이거나 완료/실패 등 전제 상태가 맞지 않음 |
| `409` | **`PART_EXISTS` / `REVISION_EXISTS` / `SLUG_TAKEN`** | 중복 품번, 동일 부품 내 동일 SHA-256 파일 재업로드, 또는 이미 사용 중인 접수함 슬러그 |
| `410` | **`LINK_REVOKED` / `LINK_EXPIRED` / `OTP_EXPIRED` / `INBOX_INACTIVE`** | 폐기/만료된 리뷰 링크, 5분 만료된 OTP, 비활성화된 접수함 |
| `413` | **`FILE_TOO_LARGE`** | STEP **50 MiB** 또는 첨부파일 **25 MiB** 용량 제한 초과 |
| `422` | **`SPEC_ACK_REQUIRED`** | `MISSING_MATERIAL`/`MISSING_TOLERANCE` 확인 체크 없이 승인 API 호출 |
| `422` | **`DFM_ACK_INVALID`** | Target 제조 공정과 일치하지 않는 DFM 체크 ID 전송 |
| `422` | **`SAME_REVISION` / `IDENTICAL_FILES` / `INVALID_TRANSFORM` / `ITEM_NOT_IN_RUN` / `ATTACHMENT_EXTENSION` / `ATTACHMENT_CONTENT_TYPE`** | Base=Target 동일 리비전 지정, 접수함 v1=v2 동일 파일 업로드, 비강체(non-rigid) 4×4 행렬, 잘못된 확장자/MIME 등 입력 검증 실패 |
| `423` | **`OTP_LOCKED`** | OTP 5회 오입력으로 잠김 → 새 OTP 코드 재발급 필요 |
| `429` | **`OTP_RATE_LIMITED`** | 10분당 3회 OTP 발급 제한 초과 → 대기 후 재시도 |
